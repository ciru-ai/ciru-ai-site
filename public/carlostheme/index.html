The inflection

From artifact to operating discipline.

The strongest story is not a single speed trick. The artifacts point to a coupled local-inference system: AMD-shaped GGUF tensor formats, tensor-aware recipes, GPU decode paths, MTP request policy, and validation scaffolding designed to agree with each other.

1. Weight formats became AMD-native.

ROCmFPX is documented as real GGUF model-weight formats, not a K/V-only compression trick. FP3, FP4, FP6, and FP8 share a 32-weight block discipline with finite UE4M3 scale bytes and direct CPU, HIP/ROCm, and Vulkan coverage.

2. Agent work became a routing problem.

The newer recipes treat the model as zones of risk: protect embeddings, attention, selected FFN paths, and other tensors that decide whether JSON, tool calls, chat, and code stay coherent.

3. Serving became adaptive.

Request-level speculative fields let clients lower draft risk without restarting the server. Dynamic Drafting then scopes feedback by mode, backend, model, and context instead of using one blunt `n_max` everywhere.

Best interpretation

Charlie's most meaningful moment here is the shift from format invention to system integration. The code starts acting as if local inference speed is only real when the model file, GPU kernels, K/V policy, MTP heads, request shape, and measurement protocol all agree.

That is why `ROCmFPX` main and the experimental branch matter together: main shows granular engineering movement; the experimental branch packages safety, profiles, and tables so other people can actually test the work.

What changed technically

The stack got reflexes.

Dynamic Drafting

The serving path can inspect prompt length and workload mode, inject speculative request fields, record accepted draft tokens, and adjust future draft depth. JSON/tool requests can be conservative; coding prompts can try deeper drafts.

Speculative model diversity

Qwen EAGLE3 state restore and Step MTP3 chained-head support extend the speculative layer beyond one happy path. The same driver learns to handle shared memory, single-head MTP, and multi-head Step-style drafting.

FP6 decode paths

The Vulkan FP6 work moves toward aligned vector dequant and safer packed-bit handling in matvec, matmul, and Flash Attention paths. That is the kernel-side reason compressed weights can still feed a fast speculative loop.

Proof discipline

Preflight scripts, model capability detection, strict benchmark settings, and README tables make the work easier to reproduce and easier to challenge. That is the difference between a fork trick and a useful local-inference workflow.
