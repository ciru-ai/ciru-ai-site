What happens during one update

The public call includes preprocessing, every FFT, the confidence decision, model learning and worker synchronization.

01

Accept frame

tracker.py

Check BGR shape, uint8 data and safe row stride.

02

Crop target window

tracker.rs

Sample the region centered on the last known position.

03

Preprocess

tracker.rs + exp044

Grayscale, log transform, normalize and apply the Hann window.

04

Forward FFT

fft2.rs / parallel layout

Convert spatial appearance into a compact frequency spectrum.

05

Correlate

sample × learned filter

Measure how strongly every circular displacement matches.

06

Inverse FFT

parallel_whole_layout.rs

Turn the correlation spectrum into a spatial response map.

07

Reduce response

peak + mean + variance

Find the best displacement while preserving deterministic ordering.

08

Calculate PSR

tracker.rs

Compare the main peak with surrounding response noise.

09

Choose outcome

PSR ≥ threshold

Decide whether the tracker is confident enough to move and learn.

10

Return result

(success, bounding_box)

Expose the decision and current coordinates through the C and Python APIs.

PSR passes?

Yes · move and learn

Shift the center by the peak offset, transform the updated appearance, blend it into the model and rebuild the filter.

No · preserve state

Report failure, keep the box unchanged and avoid teaching the model from an uncertain frame.

Why there are two execution paths

The tracking math stays the same. Only the way that work is laid out and scheduled changes.

Specialized path

fixed-multicore

  • Linux AArch64
  • Internally rounded FFT window exactly 60×36
  • Caller launched on CPU 0
  • CPUs 1–3 available to persistent workers
  • Fused, fixed-layout kernels enabled
Initialization checks architecture
window geometry
runtime capability
requested mode
Portable path

generic-single

  • Arbitrary valid window sizes
  • x86-64 and unsupported systems
  • No worker topology requirement
  • Same MOSSE formulas and decisions
  • Safe automatic fallback
A requested bounding box is first rounded to efficient FFT dimensions. Multicore eligibility depends on that internal window, not solely on the displayed box dimensions.
